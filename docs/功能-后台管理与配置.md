# 功能-后台管理与配置

## 功能：后台首页仪表盘

入口：`/admin`、`/api/v1/user/me/dashboard-layout`

实现：后台首页聚合用户、公告、空气质量、预警和服务商数据，支持拖拽、固定、缩放和保存个人仪表盘布局；页面初始化会先读取当前用户的布局配置，没有配置时回退到默认布局。

核心文件：`apps/web/src/ui/admin/pages/dashboard-page.tsx`、`apps/web/src/ui/admin/dashboard/*`、`apps/web/src/ui/admin/dashboard/hooks/use-dashboard-layout-manager.ts`、`apps/api/src/modules/user/user.controller.ts`

思路：仪表盘是聚合层，不自己发明业务数据，主要负责组合已有接口和保存用户布局；布局持久化走“用户自己的配置接口”，避免把个性化状态混进公共系统配置。

注意：布局是用户级持久化配置；固定卡片不会参与普通拖拽排序；改动组件尺寸、默认项或顺序时要注意版本兼容和老布局修复逻辑。

## 功能：城市管理

入口：`/admin/cities`、`/api/v1/city/admin/list`

实现：后台分页查看已入库城市，结合搜索条件做运维视角的数据核查。

核心文件：`apps/web/src/ui/admin/cities/*`、`apps/api/src/modules/city/city.controller.ts`、`apps/api/src/modules/city/city.service.ts`

思路：后台城市管理重在“看本地沉淀的数据”，不是替代前台搜索入口。

注意：城市列表来自本地数据库，不代表第三方全量城市库。

---

## 功能：收藏管理

入口：`/admin/favorites`、`/api/v1/admin/users/favorites/cities`

实现：后台集中查看用户收藏城市记录，并支持删除异常或不需要的收藏关系。

核心文件：`apps/web/src/ui/admin/favorites/*`、`apps/api/src/modules/user/admin-user.controller.ts`、`apps/api/src/modules/user/user.service.ts`

思路：把用户收藏做成独立运维页，避免在用户详情页里堆过多操作。

注意：删除后会直接影响大屏和用户个人收藏列表。

---

## 功能：系统配置

入口：`/admin/system`、`/api/v1/admin/system/config`、`/api/v1/system/config`

实现：后台系统页把轮询配置和 API 配额中心放在同一个页面容器中；管理员可以修改系统运行时轮询间隔，前端公开接口会定时拉取该配置，用来控制大屏、后台统计等页面的数据刷新频率。

核心文件：`apps/api/src/modules/system/system.controller.ts`、`apps/api/src/modules/system/system.service.ts`、`apps/web/src/shared/hooks/use-system-polling-interval.ts`、`apps/web/src/ui/admin/pages/system-page.tsx`

思路：把轮询间隔做成运行时配置，而不是写死在前端，方便现场调优。

注意：后台修改的是运行时配置，不需要重新发版；前端读取有自己的最小轮询间隔保护；`/admin/api-quota` 当前会直接跳到系统页的配额 Tab。

## 功能：API 配额中心

入口：`/admin/api-quota`、`/admin/system?tab=qweather`、`/admin/system?tab=amap`、`/api/v1/admin/provider-accounts/overview`、`/api/v1/admin/provider-accounts/trends`、`/api/v1/admin/provider-accounts/refresh`

实现：后台展示 QWeather 和 AMap 的账户快照、趋势和刷新结果，支持手动刷新账号数据；页面会按不同服务商展示不同的请求数口径、余额、额度和趋势图。

核心文件：`apps/api/src/modules/provider-account/provider-account.controller.ts`、`apps/api/src/modules/provider-account/provider-account.service.ts`、`apps/web/src/ui/admin/api-quota/*`

思路：服务商配额中心单独维护快照和指标点，不和普通第三方调用结果混存；展示层直接消费聚合后的 overview 和 trends 数据，不在页面里临时拼统计。

注意：数据来源分 `mock`、`live`、`snapshot` 多种；趋势依赖历史快照持续落库；`operator` 默认可查看但不可手动刷新，刷新通常只开放给 `admin`。

## 功能：后台个性化配置

入口：`/admin/profile-settings`、`/api/v1/user/me/profile`、`/api/v1/user/me/dashboard-layout`

实现：后台提供账户设置页，允许当前登录用户维护自己的用户名和邮箱，并在前端本地存储头像、展示名、简介等扩展资料；同时还支持重置新手引导状态、立即重新开始引导，以及维护首页仪表盘布局。

核心文件：`apps/web/src/ui/admin/pages/profile-settings-page.tsx`、`apps/web/src/ui/admin/profile-settings/*`、`apps/web/src/ui/admin/dashboard/hooks/use-dashboard-layout-manager.ts`、`apps/api/src/modules/user/user.controller.ts`

思路：把“真正影响后端账号数据”的内容和“纯前端体验配置”放在一个用户可理解的入口里，但底层仍保持分层，后端只接收账号资料和布局配置，头像与引导状态由前端本地持久化。

注意：用户名和邮箱走后端接口，头像、姓名、bio 走 localStorage；重置引导不会改数据库；布局和资料都属于当前用户私有配置，不会影响其他账号。
