## 环境文件放哪里

环境文件不是从仓库模板直接复制出来跑的，而是由项目维护者私发。

你需要把私发的环境文件放到这两个位置：

```text
apps/api/.env
apps/web/.env
```

如果你拿到的文件名不是 `.env`，复制后重命名成上面的目标文件名即可。

说明：

- `apps/api/.env.example` 和 `apps/web/.env.example` 只用于看字段结构。
- 实际联调、启动、对接第三方服务时，以私发的 `.env` 为准。
- `.env` 已经被 `.gitignore` 忽略，不会提交到仓库。

## 最常用的启动方式

最省事的方式是：

```bash
pnpm bootstrap:dev
```

这个命令会自动完成下面这些事情：

- 启动 Postgres 和 Redis
- 检查数据库连接信息
- 创建数据库
- 执行 Prisma generate
- 执行 Prisma migrations
- 执行 seed，初始化后台账号
- 构建 `packages/shared`
- 启动 API 和 Web

如果你想手动分步执行，也可以用下面这组命令：

```bash
pnpm install
pnpm dev:infra
pnpm prisma:migrate:dev
pnpm prisma:seed
pnpm dev
```

## 启动后访问地址

- API：`http://localhost:8080`
- Swagger：`http://localhost:8080/api/docs`
- 前端：通常是 `http://localhost:5173`
- 大屏页面：`http://localhost:5173/screen`
- 后台登录页：`http://localhost:5173/admin/login`

如果你修改了 `apps/api/.env` 里的 `PORT`，记得同步调整 `apps/web/vite.config.ts` 中的代理地址。

---

## 初始账号

初始账号来自 `apps/api/.env`。

常见字段是：

```env
INITIAL_ADMIN_USERNAME=
INITIAL_ADMIN_PASSWORD=
INITIAL_OPERATOR_USERNAME=
INITIAL_OPERATOR_PASSWORD=
```

如果执行 `pnpm prisma:seed` 时用户已存在，seed 会跳过，不会覆盖原有密码。

## 第三方服务说明

项目里有一部分能力依赖第三方服务：

- 和风天气 / 空气质量接口
- 高德地图 JS API
- 提供商额度监控相关接口

如果这些凭证还没有配好，项目通常仍然可以启动，但会出现下面这些现象：

- 后台基础功能可用
- 登录、权限、用户、公告等模块通常可用
- 地图、城市检索、空气质量、天气预警、部分统计或额度相关能力可能无数据或报错

第一次接手项目时，建议先以“项目能启动、能登录后台”为目标，再继续补第三方配置。

## 常见问题

### `pnpm` 命令不存在

先执行：

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

### Docker 不可用

先确认 Docker Desktop 已经启动，并且 `docker info` 能正常返回结果。

### `PORT 8080 is already in use`

说明本机已有进程占用了 `8080`。

处理方式：

- 结束占用 `8080` 的进程
- 或者修改 `apps/api/.env` 里的 `PORT`

### 地图不显示

优先检查 `apps/web/.env` 中的 `VITE_AMAP_KEY` 是否已经配置。
