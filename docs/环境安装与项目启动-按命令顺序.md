# 环境安装与项目启动-按命令顺序

这份文档适合第一次接手项目时直接照着执行。

默认前提：

- 你使用 macOS 或 Linux 终端
- 你已经从项目维护者处拿到了私发的环境文件
- 下面所有命令都在项目根目录执行，除非文中单独说明

---

## 1. 安装 nvm

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
```

装完后重新打开终端。

---

## 2. 安装并切换到 Node.js 22.18.0

```bash
nvm install 22.18.0
nvm use 22.18.0
nvm alias default 22.18.0
```

这个项目建议统一使用这个版本，少踩版本差异的坑。

---

## 3. 启用 pnpm

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

项目统一使用 `pnpm`，不要换成 `npm` 或 `yarn`。

---

## 4. 安装并启动 Docker Desktop

这一步没有固定命令，安装完成后把 Docker Desktop 打开即可。

项目默认通过 Docker 提供：

- PostgreSQL
- Redis

---

## 5. 安装 Git

这一步也没有固定命令，确保你本机已经能使用 `git` 即可。

---

## 6. 拉取项目代码

```bash
git clone <你的仓库地址>
cd air-monitor
```

后面的命令默认都在这个目录里执行。

---

## 7. 安装依赖

```bash
pnpm install
```

如果这里失败，先检查 Node 版本和 `pnpm` 是否正常。

---

## 8. 放置环境文件

把项目维护者私发给你的环境文件放到下面两个位置：

```text
apps/api/.env
apps/web/.env
```

如果拿到的文件名不是 `.env`，重命名后再放进去。

`apps/api/.env.example` 和 `apps/web/.env.example` 只用来看字段，不作为实际联调配置。

---

## 9. 一键启动

```bash
pnpm bootstrap:dev
```

这条命令会帮你把本地基础流程基本跑完，包括：

- 启动 Postgres 和 Redis
- 建库
- 迁移数据库
- 执行 seed
- 构建共享包
- 启动前后端

---

## 10. 访问项目

启动成功后，通常访问这些地址：

- Swagger：`http://localhost:8080/api/docs`
- 前端：`http://localhost:5173`
- 大屏：`http://localhost:5173/screen`
- 后台登录页：`http://localhost:5173/admin/login`

---

## 11. 登录后台

后台账号来自 `apps/api/.env` 中的这些字段：

```env
INITIAL_ADMIN_USERNAME=
INITIAL_ADMIN_PASSWORD=
INITIAL_OPERATOR_USERNAME=
INITIAL_OPERATOR_PASSWORD=
```

如果需要重新创建初始账号，可以再执行一次：

```bash
pnpm prisma:seed
```

---

## 12. 常见补充命令

只启动后端：

```bash
pnpm dev:api
```

只启动前端：

```bash
pnpm dev:web
```

只启动数据库和 Redis：

```bash
pnpm dev:infra
```

停止数据库和 Redis：

```bash
pnpm dev:infra:down
```

手动执行数据库迁移：

```bash
pnpm prisma:migrate:dev
```

---

## 13. 最常见的问题

### `pnpm: command not found`

执行：

```bash
corepack enable
corepack prepare pnpm@latest --activate
```

### Docker 没启动

打开 Docker Desktop，再重新执行启动命令。

### 8080 端口被占用

改 `apps/api/.env` 里的 `PORT`，或者结束本机占用 8080 的进程。

### 地图不显示

检查 `apps/web/.env` 里的 `VITE_AMAP_KEY` 是否已经配置。
